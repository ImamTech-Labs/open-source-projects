# ImamTech Labs Open Source Projects

A home for open-source software projects maintained by [ImamTech Labs](https://github.com/ImamTech-Labs). The goal is to help developers collaborate, contribute to beginner-friendly issues, and improve useful real-world applications together.

## About this repository

This repository is being set up to make ImamTech Labs projects easier to discover and contribute to. Project-specific source code, setup steps, and contribution notes will be documented in each project's own folder as projects are added.

At the moment, the repository contains this guide. There is no application to install from the repository root yet.

## Find a project or task

- Browse the [repositories in the ImamTech Labs organization](https://github.com/orgs/ImamTech-Labs/repositories) to find a project.
- Open a project's **Issues** tab to see reported bugs and suggested improvements.
- Read the project README and any linked contribution guide before starting work.
- If an issue is labeled `good first issue` or `beginner-friendly`, it may be a suitable first contribution. Ask a question in the issue if anything is unclear.

## Set up a project

Each project has its own tools and setup instructions. Use the steps in that project's README. This repository does not have root-level dependencies or a root-level setup command.

In general:

1. Install the tools listed by the project.
2. Fork the repository on GitHub, or use a branch if you have write access.
3. Clone your fork and create a branch for your change.
4. Follow the project's setup instructions.
5. Make a focused change and run the checks described by the project.
6. Open a pull request and explain what you changed.

For example:

```bash
git clone https://github.com/YOUR-USERNAME/REPOSITORY.git
cd REPOSITORY
git switch -c fix/short-description
```

Replace `YOUR-USERNAME` and `REPOSITORY` with the details for the project you are contributing to.

## Report a bug or suggest an improvement

Open an issue in the relevant project's repository. Include:

- A short, descriptive title.
- What you expected to happen and what happened instead.
- Steps to reproduce the problem, when reporting a bug.
- Screenshots, error messages, or environment details when they help explain it.

For a new idea, describe the problem it would solve and invite discussion before doing substantial work. This helps contributors agree on the approach.

## Submit a pull request

1. Check for an existing issue or pull request about the same change.
2. Keep your change focused, and follow the style already used by the project.
3. Run the checks listed in that project's README.
4. Write a clear pull request description with the reason for the change and how you checked it.
5. Link the related issue in the pull request when there is one.

Small documentation improvements are welcome. If you are new to open source, you can ask questions in the issue or pull request while you work.
